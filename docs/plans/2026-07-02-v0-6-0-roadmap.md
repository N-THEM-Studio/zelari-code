# Zelari Code v0.6.0 Roadmap

**Date:** 2026-07-02
**Target version:** 0.6.0
**Guiding principle:** *Finish the council: make the chairman real, ground the debate, ship.*

---

## TL;DR - honest summary

v0.5.0 delivered: monorepo, wizard, visible reasoning for the 5 specialists + Minosse, headless mode, and 752/752 green tests. What was **NOT** closed in v0.5.0:

- **Lucifero synthesis** is a stub - the chairman just observes (`councilApi.ts:528-532`): "Phase 13 will add full chairman integration".
- **Council grounding** - when the 5 specialists disagree, today the (empty) chairman wins or the first opinion is taken. An explicit grounding protocol is needed.
- **Visible reasoning for the chairman** - the Caronte-style header rendering in ChatStream works for the 5 specialists and Minosse, not for Lucifero (because Lucifero emits no events).

**v0.6.0 closes exactly this**: real chairman, debatable grounding, no scope creep.

---

## What NOT to do (Low Ego, carried over from v0.5.0)

Restating the cut:

- **Plugin system** - defer to v0.7+. The temptation to "load third-party tools" is real, but v0.5.0 already has `@zelari/core` with 9 subpaths; adding plugin discovery now adds 1 security surface and 0 value for the end user.
- **MCP server mode** - defer to v0.7+. v0.6 must be "complete what we have", not "expose to other tools".
- **Web UI** - defer to v0.8+. `hermes-workspace` already exists for that, and the Ink TUI is the source of truth.
- **Voice / TTS** - defer indefinitely. Low value.
- **New LLM providers** - the current 3 (Grok, GLM, MiniMax) are enough.
- **Redo Ink 6** - it works, it is tested, keep it.
- **Refactors "for cleanliness"** without a measurable reason.

## Slice 1 - Real Lucifero chairman

**Main file:** `packages/core/src/agents/councilApi.ts:528-532`

**Current state:**
```ts
if (chairman && !completedIds.has(chairman.id)) {
  callbacks.onSynthesisStart?.();
  callbacks.onSynthesisDone?.('Lucifero synthesis: see agent outputs above.');
  // ... emits member_cost with durationMs: 0 ...
}
```

**Target state:**

Lucifero receives as input:
1. The user's original task.
2. The outputs of the 5 specialists (Caronte, Nettuno, Gerione, Plutone, Minosse).
3. Its own systemPrompt (already defined in `roles.ts:181-`).

Lucifero runs `AgentHarness.run()` with:
- `model`: the same model as the council.
- `messages`: `[system(lucifero), user(rebuilt with all the outputs)]`.
- `tools`: workspace tools only (same as the specialists).
- `providerStream`: the same as the council.

Lucifero emits events:
- `agent_start` with `memberId: 'lucifer'`, `memberName: 'Lucifero'`.
- `message_delta` x N (streaming, real-time).
- `message_end` (full synthesis).
- `agent_end` with `reason: 'completed' | 'error' | 'cancelled'`.

Lucifero callbacks:
- `onSynthesisStart()` when it begins.
- `onSynthesisChunk(delta)` for every delta (so the TUI can do a typewriter effect).
- `onSynthesisDone(content, toolCalls, thinking)` at the end.

**Acceptance criteria:**

- `dispatchCouncil(...).emit('lucifer_synthesis', ...)` no longer empty.
- ChatStream shows the Lucifero header (purple, #8b5cf6) for the final message.
- Headless mode (`--headless --council --task X`) emits `memberName: "Lucifero"` in the NDJSON.
- E2E test: stub provider answering 6 invocations (5 specialists + 1 chairman) - assert all the chairman's deltas are in the output.

**Additional tests (~12 new):**
- `council-chairman.test.ts`:
  - chairman emits agent_start with the correct memberId.
  - chairman emits at least 1 message_delta.
  - chairman emits message_end with non-empty content.
  - chairman emits agent_end with a reason.
  - chairman error propagates the exit code (no swallowing).
  - empty chairman (no specialists) -> chairman does not run.

**Slice 1.5 - Robustness:**
- If the chairman fails (API error), the council is not lost: the 5 specialists' outputs remain available as a fallback synthesis.
- If the chairman emits 0 deltas, log a warn + use the last accumulated message (no silent fail).

## Slice 3 - Better council grounding

**Problem:** today, after the 5 specialists and Minosse have spoken, the "verdict" is first-opinion-wins (in many skills) or empty (in raw council). An explicit protocol is needed.

**Proposal: `groundCouncil(agentOutputs: AgentOutput[]): GroundedDecision`**

```ts
interface GroundedDecision {
  position: string;          // the "winning" position
  confidence: 'high' | 'medium' | 'low';
  dissent: Array<{           // disagreeing opinions
    agent: string;
    reason: string;
  }>;
  rationale: string;         // why this position
}
```

**Grounding strategy (3 levels):**

1. **Unanimity** (5/5 specialists agree) -> confidence: high.
2. **Majority** (3+/5 agree, with 1-2 dissenting) -> confidence: medium, dissent listed.
3. **Disagreement** (<3/5 agree) -> confidence: low, Lucifero MUST explicitly choose + justify.

**Implementation:**
- New helper in `packages/core/src/council/grounding.ts`.
- Calls a small LLM (or uses Lucifero itself) to classify each agent's position on a binary scale (agree / disagree) against a preliminary synthesis.
- Output passed to Lucifero as additional context.

**Acceptance:**
- `groundCouncil` always returns a valid object (no null).
- 5 unit tests on the 3 scenarios (unanimity, majority, disagreement).
- In `dispatchCouncil`, Lucifero's prompt includes the `GROUNDING:` section with the verdict.

**Cost:** +1 small LLM call. Mitigation: optional (`--no-grounding` flag to skip in CI, where speed matters).

## Risks & anti-patterns

| Risk | Mitigation |
|---|---|
| Chairman synthesis too verbose -> overwhelming UI | `--no-synthesis` flag to hide it in minimal mode |
| Lucifero calls the LLM with too large a context | Explicit truncation: max 4KB per specialist output passed to Lucifero |
| Grounding LLM call doubles council latency | `--no-grounding` flag + deterministic grounding cache if outputs are identical |
| Slice 1 breaks event backward-compat | `memberId/memberName` are already optional (v0.5); Lucifero emits the same shape |
| `tsc` fails on non-existent Lucifero types | Lucifero is already in `roles.ts:175-`; no new types |
