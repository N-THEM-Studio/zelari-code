
# Zelari 2.6 - Complete closure plan

**Baseline:** Zelari 2.6.0

**Target:** 2.6.1 for hardening/correctness; 2.6.2 for the per-turn budget repair; 2.7 for the full rollout of the guarantees

**Goal:** transform the capabilities already present into end-to-end guarantees, without adding new speculative features.

**Verified state 2026-08-23:** Exit Gate 2.6.1 closed; the per-turn semantics repair is verified for 2.6.2 (typecheck, 3134/3134 tests and the eval suite green). The Mission wiring residuals and the blocking candidate-vs-baseline CI remain explicitly in 2.7 (`t12`, `t15`).

> **Principle:** core capability != product guarantee. The remaining work is closing the lifecycle: `define | persist | resume | project | enforce | verify | evaluate | block regressions`.

---

## 1. Definition of Done

2.6 is truly closed when:

- every session records a complete Harness Manifest;
- the manifest changes when any model-visible behavioral input changes;
- ResourceBudget is the only authority for tool limits;
- TUI and headless rebuild the same ResourceLedger;
- `maxToolCalls` has a single unambiguous semantics;
- verification reserve genuinely protects targeted verify/repair;
- the model context contains a single Resource Status;
- `resourceReserveGate` is in the completion lifecycle;
- TaskContract does not produce false criteria;
- user steer updates TaskContract in a versioned way;
- Kraken, Gauntlet, Mission and Verification share the same TaskContract;
- budget continuation is actually wired;
- Gauntlet with zero budget goes into `hold`;
- structural changes never reduce eval coverage;
- a baseline anchor missing from the candidate is a regression;
- AnchorRunner preserves manifest hash, policy hash and real token usage;
- `maxTokens` is genuinely enforceable;
- `runGate` compares real baseline/candidate and validity;
- CI is blocking at least on Tier 0;
- 15-25 stable historical anchors exist;
- Unified Cost uses complete data.

# 3. TaskContract - parser fix

The current permissive regex must not treat every line as an acceptance criterion.

Accept as criteria only explicit patterns:

```text
- [ ] ...
- [x] ...
Acceptance: ...
Criterion: ...
Verify: ...
Test: ...
Success: ...
```

If no explicit criteria exist:

```ts
acceptanceCriteria = []
```

Normative sentences must become constraints, not automatically criteria.

Example:

```text
Fix login.
Do not change password semantics.
Keep Node 24 compatibility.
```

Expected:

```text
goal:
Fix login.

constraints:
- Do not change password semantics.
- Keep Node 24 compatibility.

criteria:
[]
```

### Exit criteria

- zero false criteria in the test fixtures;
- TaskContract can be default-on without proliferation.

---

# 4. TaskContract - steer lifecycle

Add a host-neutral updater:

```ts
interface TaskContractUpdateInput {
  current: TaskContract;
  userMessage: string;
  userSeq: number;
}
```

Relevant steers produce:

```text
task.contract_updated
```

with a monotonic version and provenance.

Rules:

- user constraints cannot be removed by agent-derived updates;
- user required criteria cannot be eliminated;
- goal rewrite only from an explicit user steer;
- append-only, never in-place mutation.

`CompactionStateSnapshot` always uses the latest TaskContract version.

# 9. `maxToolCalls`: hard vs soft

Recommended decision:

```text

```

```text

|-> deny every new billable tool call
```

Do not clamp `used`; preserve the real overrun:

```text

overrun = 2
```

Events:


# 14. Wire `resourceReserveGate`


# 17. Harness Change Classification

Do not use a hierarchy that lets `behavioral` prevail over `structural`.

Prefer:

```ts
interface HarnessChangeSet {
  structural: string[];
  behavioral: string[];
  cosmetic: string[];
}
```

Policy:

```text
structural exists
|-> full structural gate

behavioral exists
|-> add targeted behavioral anchors

cosmetic
|-> standard CI
```

A structural change can never reduce the number of tests.

For an unknown behavioral field:

```text
Tier 0 + full behavioral anchors
```

Never zero anchors.

# 21. RegressionGate - missing candidate anchor


# 23. Complete Unified Cost

Type:

```ts
interface RunCost {
  inputTokens: number;
  outputTokens: number;
  cacheHitTokens: number;
  toolCalls: number;
  modelCostUsd: number;
  toolCostUsd: number;
  wallMs: number;
}
```

North-star:

```text
cost per verified solved task
```

Computation:

```text
(modelCostUsd + toolCostUsd) / verifiedSolves
```

Report:

```text
solve rate
cost/verified solve
wall/verified solve
tool calls/verified solve
```

Possible outcome:

```text
REVIEW_REQUIRED
```

when solve improves but cost exceeds a non-hard threshold.

```text

=

+

+
```
