## Issue 2 - `grep_content` not recursive (FUNCTIONAL)

### Problem
`src/main/core/tools/builtin/search.ts:6-11`:
```ts
const GrepContentArgsSchema = z.object({
  path: z.string().min(1),  // single file
  pattern: z.string().min(1),
  ...
});
```

The parameter is named `path` but semantically it is **a single file**. It does not accept:
- Directories (e.g. `path: 'src/'` | error)
- Glob patterns (e.g. `path: 'src/**/*.ts'`)
- Multi-file (e.g. `path: 'src/cli/'` | error)

This is a big limitation for a coding agent: to search "all occurrences of X in the project" it must do N read+grep_content calls. The Hermes pattern uses `fff_grep` (directory + glob).

### Fix (2-3 h)
Extend the schema and execute to support:
1. **path** can be a file or a directory
2. New parameter **`include`**: glob pattern to filter files inside the dir (e.g. `['*.ts', '*.tsx']`)
3. Reuse the `walk()` logic from `listFiles.ts` to traverse the dir with a depth limit
4. Output unchanged but with `file: <relpath>` for every match

### Sketch
```ts
const GrepContentArgsSchema = z.object({
  path: z.string().min(1),                              // file OR directory
  pattern: z.string().min(1),
  include: z.array(z.string()).default(['*']),          // glob filter
  exclude: z.array(z.string()).default([                 // reuse listFiles defaults
    'node_modules', '.git', 'dist', 'build', '.next', '__pycache__', '.cache',
  ]),
  contextLines: z.number().int().nonnegative().default(2),
  maxMatches: z.number().int().positive().max(1000).default(50),
  maxDepth: z.number().int().positive().max(10).default(8),
});
```

### Verification
- Test `tests/unit/grep-content-recursive.test.ts`:
  - dir with 5 .ts files, 3 .md files | search a pattern, get .ts only
  - empty dir | empty result, no error
  - single-file path (legacy) | unchanged behavior
  - excluded `node_modules` is never traversed
- Backward compat: existing calls with `path: 'src/main.ts'` keep working

## Issue 3 - Diff-aware edits (FUNCTIONAL)

### Problem
- `edit_file` exists and is already string-replace (`oldString/newString/replaceAll`) in `src/main/core/tools/builtin/filesystem.ts:85-134`
- **BUT** it shows no visual diff: the user only sees "occurrencesReplaced: 3" without knowing what changed
- No fuzzy match: if the model is off by 1 char | 0 occurrences | silent fail
- No "line range" mode (e.g. "replace lines 10-15 with new content")

Aider/Cursor pattern: show the diff first, then apply. Cline/Roo pattern: `apply_diff` with fuzzy.

### Fix (3-4 h)
Add 2 new tools in `src/main/core/tools/builtin/diff.ts`:

#### Tool 1: `show_diff`
Shows a unified diff without modifying the file.
```ts
{
  name: 'show_diff',
  description: 'Show unified diff between current file content and proposed content. Read-only.',
  inputSchema: z.object({
    path: z.string(),
    proposedContent: z.string(),
    contextLines: z.number().int().nonnegative().default(3),
  }),
  execute: ... // return { diff: '<unified diff string>', hunks: [...] }
}
```

#### Tool 2: `apply_diff`
Applies a unified-format diff (parse + apply). Optional fuzzy tolerance.
```ts
{
  name: 'apply_diff',
  description: 'Apply a unified diff patch to a file. Returns the new content + diff summary.',
  inputSchema: z.object({
    path: z.string(),
    diff: z.string(),                        // unified diff format
    fuzzyMatch: z.boolean().default(false),  // 1-char tolerance
    dryRun: z.boolean().default(false),      // show the diff without applying
  }),
  execute: ... // parse diff, apply hunks, return { applied: N, skipped: N, finalContent: string }
}
```

#### Bonus: extend the existing `edit_file`
Add a `preview?: boolean` field that returns the diff without applying.

### Verification
- Test `tests/unit/diff-tools.test.ts`:
  - `show_diff` with identical content | empty diff, empty hunks
  - `show_diff` with 1 changed line | 1 hunk with -/+
  - `apply_diff` with a valid diff | applies, returns new content
  - `apply_diff` with a malformed diff | typed error, no partial apply
  - `apply_diff` with `fuzzyMatch: true` | tolerates 1 char of difference

## Implementation notes

### For recursive grep_content
- Reuse `walk()` from `listFiles.ts` by extracting it into a shared helper (`src/main/core/tools/builtin/_walk.ts`)
- Do not add dependencies (no `globby`, no `fast-glob`) - a custom regex is enough for simple patterns
- The `exclude` default copies `list_files`' for consistency

### For the diff tools
- `show_diff`: use Node's native `diff` package? No - Node has no native diff. Use a custom ~80 LOC implementation (simplified Myers algorithm) or add `diff` (1 dep, ~30kb).
- **Decision**: add `diff@^5.2.0` as a dependency. It is mature, MIT, zero transitive deps, ~30kb.
- `apply_diff`: custom unified diff parsing (~50 LOC), hunk validation, application with optional fuzzy match
- Diff visualization in the CLI: reuse `CollapsibleToolOutput` (already exists in `src/cli/components/`)

### Backward compatibility
All changes are additive or extend optional fields. No existing tool changes signature.
